# Лабораторная работа №2 — C++ на основе ЛР №1

Исходная ЛР №1: https://github.com/Mikhail008191919/LR1-abstract-data-structures

## Как запустить в Ubuntu / VS Code

Распакуй архив и **открой всю папку `LR2_refactored` в VS Code**, а не один файл.
Открой терминал в корне папки:

```bash
make
./lr2
```

`make clean` удаляет исполняемый файл, `make test` компилирует проект и запускает автоматические проверки.
Для компиляции требуются `g++` (C++17) и `make`, для тестов — `python3`.

## Структура проекта

```text
LR2_refactored/
├── main.cpp                  Главное меню, пункт 1–8
├── tasks.h                   Объявления функций запуска заданий

├── Makefile
├── structures/               Структуры из ЛР №1

│   ├── singly_list.h / .cpp        SinglyList
│   ├── array.h / array.cpp         IntArray
│   └── tree.h / tree.cpp           BSTree на основе узла Node из ЛР1
├── tasks/                    Один основной .cpp на задание
│   ├── task1_stack.cpp             Удаление лишних скобок
│   ├── task2_set.h / .cpp          АТД Множество, файловые команды
│   ├── task3_intersection.cpp      Максимальное пересечение множеств
│   ├── task4_pyramid.cpp           Максимальная высота пирамиды
│   ├── task5_tree.cpp              Правый край BST
│   ├── task6_hash.h / .cpp         Цепочки и хеширование кукушки
```

У задач №2 и №6 есть заголовки `.h`, потому что их классы используются и в других задачах.
Функции `fold()` и `magnitude()` реализованы в `task6_hash.cpp`: метод свёртки нужен обеим хеш-таблицам, а `task7_folding.cpp` выводит его работу на экран.

## Что реально переиспользовано из первой лабораторной

- **`StackDS`** (`structures/stack`) — задание 1: индексы открывающих скобок.
- **`SinglyList`** (`structures/singly_list`) — задания 2 и 6: цепочки в хеш-таблицах. К исходному списку добавлен простой последовательный обход `forEach()` и запрещено небезопасное копирование.
- **`IntArray`** (`structures/array`) — задания 4 и 8: блоки пирамиды и четыре массива LFU. Алгоритмы не перекладывают все данные в другой контейнер для видимости «использования» массива.
- **`Node`**, идея `clear()` и обход BFS из `Tree` первой лабораторной — `structures/tree`. Новая структура называется **`BSTree`**, потому что дерево поиска строится не так, как полное бинарное дерево (Complete Binary Tree) из ЛР №1. Эти алгоритмы больше не смешаны в одном классе. Для обхода `BSTree` используется `std::queue<Node*>`, как и в исходном `tree.cpp` ЛР №1: собственная `QueueDS` из ЛР №1 хранит только `int`, а здесь требуются указатели на узлы.

Неиспользуемые `queue.cpp` и `doubly_list.cpp` **не копировали** в этот проект. Их оригиналы остались в репозитории ЛР №1.

| Пункт | Ввод | Ожидаемый результат |
|---|---|---|

### Файловые операции над множеством

```bash
./lr2 --file data.txt --query 'SETADD 10'
./lr2 --file data.txt --query 'SET_AT 10'
./lr2 --file data.txt --query 'SETDEL 10'
```

Если `data.txt` не существует, то при первом успешном добавлении программа создаст его.

## Главные функции и оценки сложности

| Задание | Основная функция | Асимптотика |
|---|---|---|
| 1 | `fixParentheses()` | O(n) время и память |
| 2 | `IntSet::add/del/has()` | ожидаемо O(1) при умеренных цепочках, худшее O(n) |
| 3 | `runSetIntersection()` | ожидаемо O(k²·m + k·m log m) для k множеств по m элементов |
| 4 | `maxPyramid()` | O(n log n) |
| 5 | `BSTree::insert()` / `rightView()` | вставка O(h), обход O(n); h — высота дерева |
| 6 | `ChainTable::add()`, `Cuckoo::add()` | цепочки: ожидаемо O(1), худшее O(n); кукушка: поиск O(1), вставка может вызвать перестроение |
| 7 | `fold()` | O(d) по количеству цифр (для `int64_t` d ограничено) |
| 8 | `LFUCache::get/set()` | O(c), c — вместимость кэша |

Время в задании 6 измеряется на текущей машине, поэтому численные значения при каждом запуске отличаются.
